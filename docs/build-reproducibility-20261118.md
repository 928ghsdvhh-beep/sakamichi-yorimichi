# 再生成の不整合を解消

確認対象 main: `3a969d283e88b6d6587de8ad243485212768a8bc`。

## 確認した原因

最新 main の既存 dist を残したビルドでは55 HTMLを生成し、記事欠落は再現しませんでした。
以前の「再生成で追加記事が再現できない」という評価を、この検証で確認した原因に訂正します。

空の dist からは `assets/share-card.png` の保存先ディレクトリがなく失敗しました。
またCSS 6ファイル・JavaScript 2ファイル・Google所有権確認HTMLの計9ファイルは
生成元に存在せず、コミット済み dist に依存していました。

## 修正

- 既存9ファイルを内容を変えず `src/static/` に保存し、ビルド冒頭で出力先へコピー。
- OG画像生成時に保存先ディレクトリを作成。
- 購入確認記事の末尾改行を明示し、コミット済みHTMLとバイト単位で一致。
- 一時ディレクトリで3条件の再生成と既存静的監査を実行する `scripts/check_build.py` を追加。

## 検証

`python scripts/check_build.py` が成功。空の出力先・連続2回目・既存 dist 付きの全3条件で、
71ファイルがコミット済み dist とバイト単位で一致。55 HTML（Google所有権確認を含む）、
サイトマップ・robots・画像・CSS・JavaScriptを保全し、広告アンカー・Tracking ID・計測script・
記事本文・URL・デザインにも差分なし。既存静的監査は54ページ、issues 0。

本PRは公開内容を変更せず、今後の変更で既存出力の残存に依存しないようにする修正です。
